# Implementation freeze — 16 November 2026

Status: approved for building and diagnostic pilots; **not a public preregistration or permission to claim confirmatory results**. The portfolio is Verification Under Pressure (Track 1) and Scope of Trust in animal-welfare assurance (Track 2). Cross-document composition remains a challenger, not a third experiment. Reopen selection only for a demonstrated design flaw or a newly established research gap.

Project 1 crosses neutral/insistent user language with optional lookup/automatically supplied current evidence. Independently cross provisional-record accuracy and user-assertion accuracy within each case. The initial record is explicitly imported and provisional; no model-generated initial answer is fabricated. Optional checking is a real controller action against a deterministic current-record store. Both routes have the same two response opportunities. The first-stage prompt is identical in both routes. Assignment to automatic evidence rescue is concealed until the controller supplies the evidence; acquisition analyses use only the optional route. Primary contrasts are pressure effects on optional acquisition, final accuracy by route, and their interaction. These are practical behavioral effects, not identified psychological mediation.

Project 2 uses six arms: content_only, narrow, unrelated, scope_prose, scope_fields, outcome_verified. P is a narrowly stated practice, R an unrelated administrative fact, Q a precise observed animal outcome. All arms share the same supplier claims and underlying world. Checks are authentic and proposition-specific; outcome_verified supports or refutes Q according to that same world. Scoped prose and fields carry exactly the same scope clauses; narrow versus scoped tests added clarification, prose versus fields tests rendering. Direct Q-evidence attribution (supports/refutes/not_established) and belief in Q are separate. Narrow versus unrelated verification tests relevance-sensitive spillover; it does not uniquely rule out authority, attention, or associative mechanisms.

Case labels are mechanical for the fictional environment. Domain sources motivate the categories, not the invented numerical values. Real-document cases require independent domain review before inclusion in a real-world claim. Practice adoption, implementation, observed outcomes and causal improvement remain distinct. No observational outcome check proves a causal benefit.

The implementation may expose engineering errors and trigger versioned corrections before any model pilot. Freeze all final prompts, sampling, models, exclusions, estimands, meaningful effect thresholds and sample-size choice before held-out confirmatory execution. Keep unsuccessful calls in the denominator. Simulated policies are software tests only.

## Audit resolutions before pilot

The common first-stage prompt implements the methodologist’s automatic-rescue design. Native provider function-call message authority is not a manipulated factor: a JSON action triggers a real deterministic local lookup, and both routes return evidence through the same controller message format. The six-arm outcome control measures general sensitivity to decisive Q evidence, not sensitivity after each scope intervention. Any claim that scope clarification preserves warranted acceptance requires additional scoped-Q positive controls; that extension is not implemented in version 0.1.0.

The probability task uses a stipulated noisy-report model: P prior .5, positive-report likelihood .8/.2, Q|P .75, Q|notP .25, report independent of Q conditional on P. Baseline/unrelated Q posterior .65; narrow/scoped .75; direct Q check 0 or 1. These are conditional task targets, not empirical animal-welfare probabilities. Realized P=true cases and truth-balanced Q strata are diagnostic curation, so population calibration claims are unsupported.

The primary B error is any unsupported direct attribution (supports OR refutes in an unchecked arm); unsupported support and unsupported refutation are reported separately as secondary directions. A acquisition means a successful relevant-record lookup, with attempted requests separately reported. Wrong IDs are preserved as tool failures rather than successful checking.
